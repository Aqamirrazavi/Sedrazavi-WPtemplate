## ADR 001: WordPress-Native Rendering as Customer-Facing Product

### Context
The repository contained a full-stack React/Vite development app alongside a WordPress theme and plugin suite. Treating the public website as an SPA that overrides WordPress templates causes serious performance regressions (LCP, FID), degrades search engine indexability, breaks plugin compatibility, and violates WordPress core standards.

### Decision
WordPress PHP templates and native Elementor/Gutenberg builders are established as the primary, customer-facing rendering engine. 
- Public visitors receive server-rendered semantic HTML generated by PHP.
- React is constrained strictly to the administrative developer portal, the Sovereign Designer Toolbox modal, and interactive client portal shells.
- Front-end React hydration is never required for public page viewing.

### Consequences
- **Positive:** Maximum Core Web Vitals scores, instant LCP, clean SEO crawlability, and compatibility with standard WordPress caching plugins (Varnish, Redis, LiteSpeed).
- **Trade-off:** Interactive React dashboards must bridge with WordPress via REST endpoints with strict nonce and capability checks.

## ADR 002: Default-Deny Confidentiality for Client Case Dossiers

### Context
Litigation dockets and client legal cases (`case` CPT) were initially registered with `'public' => true`, creating an acute risk of public indexing, search enumeration, and accidental disclosure of attorney-client privileged information.

### Decision
CPT `case` is made strictly private and default-deny:
- `'public' => false`
- `'publicly_queryable' => false`
- `'exclude_from_search' => true`
- `'has_archive' => false`
- `'rewrite' => false`
- `'show_in_rest' => false`

To fulfill the need for public law firm marketing and educational precedent showcasing, a separate CPT `case_study` (نمونه‌پرونده‌ها و دعاوی موفق) is created with `'public' => true` and dedicated sanitization.

### Consequences
- **Positive:** Complete confidentiality of legal dockets. Zero leak in sitemaps, search, or public URLs.
- **Trade-off:** Staff must access client dossiers via authenticated admin screens or protected REST routes.

## ADR 003: Nonce Is Not Authorization; Mandatory Capability and Ownership Checks

### Context
In initial REST route handlers, a valid `X-WP-Nonce` header was accepted as proof of authentication or permission to overwrite theme settings and access case lists. Under WordPress security standards, nonces protect against CSRF; they do NOT authenticate identity or authorize actions.

### Decision
1. `check_logged_in_permission` requires `is_user_logged_in()`. Nonce alone never grants logged-in privileges.
2. `check_save_permissions` requires `current_user_can('manage_options')` or `edit_theme_options` AND valid CSRF nonce.
3. `check_case_access_permission` validates role capabilities (`manage_options`, `edit_posts`) and enforces per-object ownership checks for clients (`$case_post->post_author == current_user_id`).

### Consequences
- **Positive:** Complete elimination of IDOR, unauthorized privilege escalation, and settings tampering.
- **Trade-off:** REST client requests must ensure cookies/sessions accompany requests.

## ADR 004: Elementor-First and Gutenberg-Native Co-Existence

### Context
Users require full freedom to design websites using either Elementor (the industry leading visual builder in Persian/global WordPress markets) or Gutenberg (WordPress native block editor) without style leaks, CSS container conflicts, or broken inspector panels.

### Decision
1. **Elementor Suite:** Official Elementor widget classes registered in a dedicated category `sedrazavi-sovereign-suite` with controls divided into Content, Style, and Advanced.
2. **Gutenberg Suite:** Native server-side rendered blocks registered via `register_block_type` under category `sedrazavi-sovereign` with visual InspectorControls.
3. **Universal Fallback:** Standalone shortcodes registered as cross-builder adapters for legacy themes, classic editors, and WooCommerce.

### Consequences
- **Positive:** Universal compatibility across all WordPress setups without locking the user into a specific builder.
- **Negative:** Three adapter entry points must be maintained and kept in sync with the asset banks.

## ADR 005: Zero-CDN Purity Guarantee

### Context
Reliance on external CDNs (Google Fonts, unpkg, cdnjs, FontAwesome) introduces severe failure points, including network blocking/censorship in domestic networks, GDPR/privacy compliance violations, and latency overhead.

### Decision
All 402 sovereign assets (66 vector backgrounds, 72 widgets, 66 dividers, 66 badges, 66 sections, 66 motions, 66 icons) and typography (Vazirmatn) are bundled locally as pure inline SVGs, CSS3 keyframes, and local Woff2 webfonts. Zero external network requests are permitted.

### Consequences
- **Positive:** 100% offline functionality, intranet/air-gapped deployment readiness, zero third-party tracking, and instant asset rendering.
- **Trade-off:** Theme and plugin packages include the asset definitions locally (~14 MB total theme package).

## ADR 006: Query Parameter Allowlisting and Preview Protection

### Context
Header and footer archetypes were switchable via `$_GET['header_style']` and `$_GET['footer_style']` without restrictions, allowing arbitrary class injection and creating duplicate URLs for search engines.

### Decision
1. Strict allowlists enforced for valid archetypes (`frosted-glass`, `minimal-clean`, `dark-luxury`, etc.).
2. Query parameter overrides are ignored for anonymous visitors and only honored if `current_user_can('edit_theme_options')` or inside the WordPress Customizer preview.
3. When an active preview parameter is detected, `wp_robots_no_robots()` is automatically hooked to inject `<meta name="robots" content="noindex, nofollow">`.

### Consequences
- **Positive:** Complete protection against search engine duplicate content penalties and cache poisoning.
- **Trade-off:** Public visitors only see the official option chosen in theme settings.
